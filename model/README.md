# model — 등급 추정 모델 학습

서버(`beec`)가 읽는 `beec/src/main/resources/model.json`을 만드는 학습 코드입니다.
서버는 모델을 실행하지 않고, 여기서 미리 계산한 단지별 예측값과 시기별 판정을 읽기만 합니다.

## 실행

```bash
pip install -r model/requirements.txt
python model/train.py          # 저장소 루트에서
```

같은 입력이면 같은 `model.json`이 나옵니다(시드·하이퍼파라미터 고정). 실행 기록은 `model/train-report.json`에 남습니다.

| 파일 | 내용 |
|---|---|
| `train.py` | 학습 · 5-fold 교차검증 · 시기별 게이트 · 예측값 생성 |
| `train-report.json` | 학습 설정, 입력·출력 파일 SHA-256, 라이브러리 버전, 시기별 결과, 비교 기준 성능 |
| `requirements.txt` | 학습에 쓴 라이브러리 버전 |

## 흐름

```
seoul-apartments.json  (서울 아파트 2,888개 + 인증 매칭 정답 324개)
   │
   ├─ 입력 변수 8개 → 14열 (복도유형·난방방식 원-핫)
   ├─ GradientBoosting (트리 200, 학습률 0.05, 깊이 3, subsample 0.8)
   ├─ 5-fold 교차검증 — 성능은 실측 연속값 223개로만 측정
   ├─ 준공 시기별 오차 → point / range / refuse 판정
   └─ 전체 정답으로 다시 학습 → 단지 2,875개 예측
   ▼
model.json  (overall · gate · predictions · features · featureImportance · method)
```

## 게이트 규칙

- 검증 표본 8개 미만이면 **추정 안 함**
- 오차 ≤ 30이고 실측 검증 표본이 8개 이상이면 **등급**
- 오차 ≤ 45이면 **범위**. 실측 표본이 8개 미만이면 범위 폭은 시기 오차와 전체 오차 중 큰 값
- 그보다 크면 **추정 안 함**

등급 한 칸 폭이 30~40 kWh/m²·yr라서, 오차가 그보다 크면 등급을 말하는 순간 틀린 칸을 가리킬 수 있습니다.

## 데이터 준비 단계 (이 스크립트 이전)

`seoul-apartments.json`은 아래 원본을 결합해 만든 결과물입니다. 원본 파일은 저장소에 포함하지 않았습니다.

- 서울시 공동주택(K-apt) 정보 — 단지 속성
- 한국에너지공단 건축물 에너지효율등급 인증 실적 — 1차에너지소요량, 인증일자
- 한국에너지공단 인증현황 — 등급만 있는 인증 (구간 중앙값으로 라벨)

이 단계에서 이상값 정리(연면적 54 · 세대수 67 · 주거전용면적 32건), 준공연도 → 단열기준 시기 변환, 단지명 기반 인증 매칭, 재건축 오매칭(인증일자 − 준공연도 ≥ 15년) 49건 제외를 했고, 그 기록이 `seoul-apartments.json`의 `meta`와 각 단지의 `matchedBy` · `labelSource` · `excludedReason`에 남아 있습니다.
